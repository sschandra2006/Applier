## 1. Concurrency & Execution Context Assessment

### ⚠️ Critical Finding: In-Process Event Loop Execution
**Playwright execution runs directly inside the Node.js Express process/event loop.**

In [`backend/src/automation/automation.service.js`](file:///f:/Applier/backend/src/automation/automation.service.js):
```javascript
// Line 207:
executePlan(jobId, targetUrl, steps, answers, 0).catch(err => {
    console.error(`[AutomationEngine] Execution error for job ${jobId}:`, err);
});
```
- **Execution Mechanism:** When `POST /api/v1/automation/webhook/plan` arrives, `saveAndStartPlan()` executes `executePlan` as an unmanaged floating asynchronous promise.
- **Worker Isolation:** **NONE.** There is no worker thread (`piscina`), no child process isolation, and no external message queue (BullMQ/Redis/Celery).
- **Process Impact:**
  - Launching Chromium instances directly on the Node host consumes 150MB–400MB RAM per running job.
  - Browser crashes, memory leaks, or unhandled promise rejections directly threaten the stability of the main API server.
  - Concurrency is bounded strictly by host server RAM. 10 concurrent users running applications will spawn 10 headless Chromium processes concurrently on the same machine.

## 3. Crawler & Scanner Analysis (`scanUrl`)

- **Scope:** Multi-page BFS crawl up to `maxPages = 10` and `maxDepth = 2`.
- **Navigation Timeout:** 30,000ms (`page.goto(url, { waitUntil: 'domcontentloaded', timeout: 30000 })`).
- **Network Idle Soft Timeout:** 8,000ms (`page.waitForLoadState('networkidle', { timeout: 8000 })`).
- **Link Discovery:** Evaluates DOM for `a[href]`, `form[action]`, `button[onclick]`, and `nav a`. Filters strictly for same-origin URLs:
  ```javascript
  const isSameOrigin = (absUrl.origin === origin);
  ```
- **CTA Detection:** Regex tests for keyword patterns: `/apply|register|portal|scholarship|fresh|renewal|epass|buddy4study/i`.
- **Screenshots:**
  - Landing screenshot: `await page.screenshot({ fullPage: true })` converted to base64.
- **Page Cleanup:** Explicit `await page.close().catch(() => {})` in `finally` block of the page loop.

## 4. Execution Engine Analysis (`executePlan`)

The engine iterates over an array of `ExecutionStep` objects generated by the AI:

### 4.1. Step Types & Actions
1. **`navigate`:**
   - Navigates to `step.url || targetUrl` with 30s timeout and 10s network idle soft timeout.
2. **`fill`:**
   - Retrieves answer from `answers[step.field] || step.value`.
   - Executes `await page.fill(step.selector, String(value), { timeout: 10000 })`.
   - **DOM Event Dispatch Fallback:** If `page.fill` throws, uses `page.evaluate()` to set `el.value = val` and manually dispatches standard `input` and `change` browser events.
3. **`click`:**
   - Executes `await page.click(step.selector, { timeout: 10000 })`.
   - **Fallback:** Evaluates `document.querySelector(sel).click()` in DOM.
4. **`select` (`selectOptionRobust`):**
   - 4-Tier Strategy:
     1. Playwright `page.selectOption(selector, value, { timeout: 3000 })`.
     2. Native DOM evaluation: Checks exact option `value`, exact `textContent`, or substring label match. Dispatches standard `change`/`input` events + jQuery/Select2 events (`$(el).val(...).trigger('change').trigger('select2:select')`).
     3. Select2 Custom UI click: Locates `.select2-container`, clicks to open dropdown, fills `.select2-search__field`, clicks matching `.select2-results__option`.
     4. Playwright forced label/value select with 5000ms timeout.
5. **`upload`:**
   - Downloads file from `documentUrl` (local or remote).
   - Passes buffer to `DocumentProcessingEngine.prepareDocument(buffer, mimeType, step.constraints)`.
   - Writes processed buffer to OS temporary file (`os.tmpdir()`).
   - Executes `await page.setInputFiles(step.selector, tempFilePath)`.
6. **`screenshot`:**
   - Captures full-page screenshot as base64 and attaches to job logs as `base64Receipt`.

## 5. Pause & Resume Checkpoints (OTP & CAPTCHA)

When `step.type === 'pause'`:
- **Pause Reason:** Extracted as `pauseReason: 'CAPTCHA' | 'OTP'` with status `PAUSED_CAPTCHA` or `PAUSED_OTP`.
- **CAPTCHA Screenshotting:**
  - If `step.captchaSelector` is provided, locates element: `const captchaEl = await page.$(step.captchaSelector)`.
  - Captures element screenshot: `const buf = await captchaEl.screenshot()`.
  - Encodes to base64 and stores in `job.pauseContext.captchaImageBase64`.
  - If element is not found, falls back to full-page screenshot.
- **In-Memory Holding Loop:**
  ```javascript
  let answered = false;
  let pollCount = 0;
  while (!answered && pollCount < 60) {
      await page.waitForTimeout(5000);
      const currentJob = await AutomationJob.findById(jobId);
      if (currentJob && currentJob.status === 'RUNNING') {
          answered = true;
          // Reload updated answers from MongoDB
          break;
      }
      pollCount++;
  }
  ```
- **Timeout:** 5 minutes (60 iterations $\times$ 5 seconds). Throws error if user fails to respond.
- **Resumption (`resumePlan`):**
  - Triggered via `POST /api/v1/automation/resume`.
  - Updates `state.answers` in MongoDB with the user's OTP or CAPTCHA code.
  - Updates `AutomationJob` status to `RUNNING`.
  - The in-memory polling loop inside `executePlan` observes `RUNNING`, reloads `answers`, and advances to step $i+1$.

## 6. Error Handling & Recovery Callbacks

- If any step throws an unhandled error:
  - Catches error in `executePlan()` $\rightarrow$ calls `logJobError(jobId, error.message)`.
  - Updates `AutomationJob.status = 'FAILED'`.
  - Sends asynchronous diagnosis request to AI Service:
    ```http
    POST http://127.0.0.1:8000/api/v1/ai/execute
    {
      "intent": "recover_error",
      "raw_data": { "logs": job.logs, "message": error.message, "targetUrl": "unknown" }
    }
    ```
  - AI `RecoveryAgent` analyzes failure and logs insight.
- Browser instance is guaranteed to close in `finally { await browser.close(); }`.

## 7. Playwright Audit Summary

| Area | Current Implementation Status | Risk Assessment |
| :--- | :--- | :--- |
| **Event Loop Isolation** | **None** (runs in main server process) | **CRITICAL RISK:** Scalability bottleneck & memory exhaustion under load. |
| **Browser Cleanup** | Strict `try / finally` closure | **LOW RISK:** Clean process termination observed. |
| **Option Selection** | 4-tier robust fallback including Select2 | **LOW RISK:** High resilience against Indian portal dropdowns. |
| **File Uploads** | Passes through DocumentProcessingEngine | **LOW RISK:** Guaranteed format and size compliance before upload. |
| **Pause Mechanism** | Polling loop keeping browser context open | **MEDIUM RISK:** Holds browser in RAM for up to 5 minutes per pause. |
| **Anti-Bot / Stealth** | Standard Chromium + custom User-Agent | **MEDIUM RISK:** Lacks Playwright-extra stealth plugins; Cloudflare/Akamai may block. |
